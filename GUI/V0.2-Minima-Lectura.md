# GUI minima de lectura para V0.2

Este documento define la GUI minima de solo lectura prevista para `V0.2`.

## 1. Objetivo

No busca operar todo el sistema. Busca validar visualmente que la base SQLite contiene correctamente la planificacion estructurada.

La pregunta que debe responder esta GUI es simple:

> "Puedo navegar desde una temporada hasta una sesion planificada concreta sin tocar SQL ni leer markdown?"

## 2. Alcance funcional

La GUI minima cubre solo lectura de planificacion.

Incluye:
- temporadas,
- bloques,
- semanas,
- sesiones planificadas.

No incluye aun:
- edicion,
- registro diario,
- importaciones Garmin,
- analisis,
- ajustes,
- autenticacion,
- ni acciones de agentes.

## 3. Vistas

### Vista 1. Temporadas

Objetivo:
- mostrar las temporadas disponibles en la base.

Datos a mostrar:
- `season_code`
- `season_name`
- `start_date`
- `end_date`
- `status`

Accion principal:
- abrir el detalle de una temporada.

### Vista 2. Bloques de una temporada

Objetivo:
- mostrar la secuencia de bloques meso de la temporada seleccionada.

Datos a mostrar:
- `block_code`
- `block_name`
- `phase_name`
- `sequence_order`
- `start_date`
- `end_date`
- `objective_primary`

Accion principal:
- abrir el detalle de semanas del bloque.

### Vista 3. Semanas de un bloque

Objetivo:
- mostrar las semanas micro del bloque seleccionado.

Datos a mostrar:
- `week_code`
- `sequence_in_block`
- `start_date`
- `end_date`
- `week_role`
- `objective_primary`
- `target_volume_hours_min`
- `target_volume_hours_max`

Accion principal:
- abrir el detalle de sesiones planificadas.

### Vista 4. Sesiones planificadas de una semana

Objetivo:
- mostrar el detalle diario de la semana seleccionada.

Datos a mostrar:
- `session_date`
- `day_name`
- `planned_type`
- `objective`
- `primary_session`
- `complementary_session`
- `intensity_class`
- `duration_min`
- `duration_max`
- `is_key_session`

Accion principal:
- ninguna accion compleja; lectura y verificacion visual.

## 4. Navegacion

Flujo minimo:
1. Entrar en lista de temporadas.
2. Elegir `2026`.
3. Ver lista de bloques.
4. Elegir `B1`.
5. Ver lista de semanas.
6. Elegir `Semana-01`.
7. Ver sesiones planificadas de lunes a domingo.

## 5. Requisitos visuales minimos

- lectura clara de tablas o listas,
- jerarquia evidente entre temporada, bloque, semana y sesion,
- migas de pan o contexto visible,
- tiempos y objetivos faciles de escanear,
- y cero sobrecarga visual innecesaria.

## 6. Consultas minimas necesarias

### Temporadas
```sql
SELECT season_id, season_code, season_name, start_date, end_date, status
FROM plan_seasons
ORDER BY season_code;
```

### Bloques por temporada
```sql
SELECT block_id, block_code, block_name, phase_name, sequence_order, start_date, end_date, objective_primary
FROM plan_meso_blocks
WHERE season_id = ?
ORDER BY sequence_order;
```

### Semanas por bloque
```sql
SELECT week_id, week_code, sequence_in_block, start_date, end_date, week_role, objective_primary,
       target_volume_hours_min, target_volume_hours_max
FROM plan_micro_weeks
WHERE block_id = ?
ORDER BY sequence_in_block;
```

### Sesiones por semana
```sql
SELECT planned_session_id, session_date, day_name, planned_type, objective, primary_session,
       complementary_session, intensity_class, duration_min, duration_max, is_key_session
FROM plan_planned_sessions
WHERE week_id = ?
ORDER BY sequence_in_week;
```

## 7. Criterio de terminado

La GUI minima se considera terminada cuando:
- el usuario puede abrir `2026`,
- puede navegar hasta `B1` y sus semanas,
- puede ver las 7 sesiones de una semana,
- y la informacion coincide con lo que existe en SQLite.
